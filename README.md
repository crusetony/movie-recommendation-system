# TMDB 实时智能电影推荐系统

这是一个用于本科毕业设计的本地 Web 应用。用户用自然语言描述观影需求，系统将需求解析成类型、地区、语言、年代、片长和评分等条件，实时查询 TMDB，并通过可解释的本地排序算法返回推荐结果。

公开源码：[crusetony/movie-recommendation-system](https://github.com/crusetony/movie-recommendation-system)。下载与部署从下文“从 GitHub 获取源码”开始；模型、密钥、实验档案和课程文稿保存在本机。

本项目不再爬取豆瓣内容，不维护完整电影数据库。电影条目、海报、评分和简介均在请求时从 TMDB 获取，内存缓存仅用于减少短时间内的重复请求。

前端保留深蓝电影主题、酸黄强调色与大字海报首页。打开根网址先显示 CINEMA 加载动画，再进入电影海报开场页，点击“开始选片”进入推荐工作台；移入片名预览《出租车司机》《春光乍泄》和1982年《银翼杀手》的真实海报，点击片名、行内箭头或海报打开对应电影的简介与详情。

加载画面直接放在入口 HTML 中，JavaScript 下载期间也能显示。应用挂载后等待字体与首页首张海报加载或失败，保留约1.2秒开场后淡出；资源停滞时最多等待3.5秒，再用0.32秒退出。它不依赖后端就绪，也不显示虚构的加载百分比。减少动态效果时跳过动画与固定开场等待。页内导航不重播；直接打开 `#workbench / #catalog / #history / #library / #experiment` 仍进入对应页面。

首页右侧电影精选与左侧说明使用相同的淡入上移效果，加载屏结束后再播放；减少动态效果时不播放。详情、推荐结果/历史与片单海报等比例铺满容器，避免非标准比例图片造成上下留白；边缘可能轻微裁切，不拉伸原图。

首页随窗口高度铺满，下方保留三项推荐方式。整块页脚和圆形向下箭头已移除，TMDB说明收进“使用说明”。

统一导航顺序为“电影推荐 → 电影搜索 → 推荐历史 → 我的片单”，实验室为次入口。地址分别为 `#workbench / #catalog / #history / #library / #experiment`，首页为 `#top`；直接打开、刷新、浏览器前进/后退均按地址选择页面。已打开工作页保持挂载，往返首页和切换页面保留未提交输入与实验草稿。

推荐输入区保留一个标题、需求输入、灵感示例和主按钮；图片/参考电影按需展开，选择参考或恢复带参考的历史需求时自动展开。正常系统状态收为导航小标记，点击查看真实连接、解析模型、缓存与视觉状态；失败和实际降级直接提示，检测失败不会把旧状态当作仍然就绪。

“随机灵感”从24段本地观影需求中随机填入一段，连续点击避开当前原句；文字可以继续编辑，只有点击“获取推荐”才提交。原有三个固定主题按钮已移除。

结果先显示数量与简短需求摘要，完整解析和调用诊断收进“技术详情”。未添加视觉参考、尚无评分属于正常未参与状态，原因仍可在技术详情中查看。推荐卡片使用紧凑的直立海报（桌面宽180px，窄屏90–124px），元数据合为文字行，简介默认三行且可展开全文；保留推荐理由、收藏/想看/看过、十分制评分、电影详情和可展开的算法评分。搜索与片单也使用紧凑海报卡片。

评分与本地保存/历史规则集中在导航的“使用说明”。保留既有确认、容量、上游分页限制提示与减少动态效果适配；不改推荐算法、权重、模型或存储版本。

本轮验证见 [2026-10-09 前端精简验证](experiments/VALIDATION_2026-10-09_COMPACT_UI.md)。此前的 [首页与海报](experiments/VALIDATION_2026-10-08_JIEJOE_UI.md)、[推荐卡片](experiments/VALIDATION_2026-10-08_RESULT_CARDS.md)、[玻璃主题](experiments/VALIDATION_2026-10-08_GLASS_UI.md)、[motion动效](experiments/VALIDATION_2026-10-08_MOTION_UI.md) 和 [2026-10-06主题](experiments/VALIDATION_2026-10-06_UI.md) 均是历史时点记录。

## 系统架构

```text
React + Material UI
        ↓ POST /recommend
FastAPI
        ↓
自然语言解析（本地规则 + 可选 OpenAI Responses 兼容服务）
        ↓
TMDB Discover / 关键词 / 人物片单 / 相似与关联推荐
        ↓
详情增强（关键词、导演、演员、图片）
        ↓
多语言文本向量（可选、延迟加载、SQLite 缓存）
        ↓
六维可解释评分与排序
```

大模型只负责把复杂自然语言转换成结构化条件，可通过 `OPENAI_BASE_URL` 接入 DeepSeek 等兼容 Responses API 的服务。即使未配置或调用失败，系统也会自动使用本地规则解析；电影候选始终来自 TMDB。

输入既可以是简短观影需求，也可以是一段影评或观后感。影评会整体发送给 DeepSeek，提取被评论片名、主题、情绪、喜欢的风格和明确不喜欢的元素；随后系统结合 TMDB 相似电影、关联推荐与关键词召回，并由本地可解释评分完成最终排序。DeepSeek 不可用时会降级到有限的本地影评规则。

主题规则与AI合并会过滤明确否定的题材，例如“不要爱情”不会再次加入正向主题。常见主题保留中文说明与英文召回词，最多8个去重检索词参与搜索，完整解析可查看这些词；本地规则的词汇覆盖仍有限。本轮验证见 [解析与随机灵感验证](experiments/VALIDATION_2026-10-09_QUERY_PARSING.md)。

## 推荐接口

### `POST /recommend`

请求：

```json
{
  "query": "想看一部节奏快、两小时以内、不太血腥的韩国悬疑片",
  "max_recommendations": 20,
  "exclude_movie_ids": [],
  "feedback": []
}
```

响应中的主要字段：

- `query_analysis`：系统解析出的筛选条件。
- `recommendations`：经过本地算法排序的 TMDB 电影。
- `match_score`：0 到 1 的综合评分，保留用于排序和兼容旧调用方。
- `score_breakdown`：固定六维评分结构，包含每项得分、权重、贡献值、可用状态和证据。
- `score_breakdown.components[].algorithm`：该分量实际使用的算法版本；文本项会明确为向量语义或词项降级。
- `recall_sources`：候选进入推荐池的来源，例如条件检索、关键词、导演作品、参考电影相似片。
- `reasoning`：根据真实电影信息生成的推荐理由。
- `warnings`：没有完全匹配结果时采用的放宽说明。
- `diagnostics.semantic_mode`：`vector_semantic` 或 `lexical_fallback`。
- `diagnostics.semantic_fallback_reason`：依赖、模型文件、设备或向量异常时的具体降级原因。
- `diagnostics.text_vector_cache_hits/misses`：本次电影文本向量缓存统计。
- `rank_before_mmr` / `rank_after_mmr`：融合相关性排序与多样性重排后的名次。
- `diversity_penalty` / `diversity_reason`：候选与已选结果的最大冗余度及可解释原因。
- `diagnostics.mmr_lambda`：本次多样性重排使用的相关性—多样性系数。

## 推荐排序

```text
配置权重 = 25% × 硬条件/意图 + 20% × 文本语义 + 15% × 视觉相似度
         + 15% × 贝叶斯质量 + 10% × 热度 + 15% × 个人评分偏好

实际权重_i = 配置权重_i / 所有可用分量的配置权重之和
综合分 = Σ(分量原始分_i × 实际权重_i)

MMR = λ × 综合分 − (1 − λ) × 与已选结果的最大电影间相似度
```

六项配置集中在 `backend/services/scoring_config.py`，对应环境变量为
`SCORE_WEIGHT_*`，其总和必须严格等于 1。视觉或反馈不可用时不会以 0 分拉低
结果，而是退出本次融合，其权重自动分配给仍可用的分量。接口同时返回配置权重、
实际权重、加权贡献、可用状态、证据和算法版本。

明确违反类型、排除类型、国家、语言、年代、片长、评分、导演、演员或低暴力条件
的电影会在融合排序前过滤；TMDB 元数据缺失只按未知项降低硬条件得分，不会被误判
为违规。如果当前候选全部不满足可安全放宽的数值条件，系统只放宽评分 1 分、片长
15 分钟或年代 5 年，并在 `warnings` 中逐项说明，不会静默放宽国家、语言或排除项。

融合评分完成后，系统只在已通过硬条件过滤的候选中执行 MMR。默认 `λ=0.75`，
电影间相似度按可用特征动态归一化组合文本向量、海报向量、类型 Jaccard、国家、
年代距离、系列和导演；模型不可用时仍可使用 TMDB 元数据稳定重排。MMR 只改变结果
顺序，不改写融合分或把硬条件不合格影片重新加入列表。`λ=1` 时严格保持原融合排序。
配置集中在 `MMR_*` 环境变量中，算法版本为 `hybrid-mmr-v1`。

### 电影详情、片单与个人星级

点击推荐电影标题、海报或“电影详情”，也可点击开场精选海报、视觉参考电影和片单电影，
打开本地详情弹窗。数据复用现有 `GET /movies/{tmdb_id}` 的 TMDB 返回，展示完整简介、
演职员及角色、类型、关键词、语言、国家等。缺失资料和加载失败明确提示，支持重试；
切换影片/关闭时取消请求，过期响应不能覆盖新影片。详情可以设为视觉参考，保留需求文本，
不自动发起推荐；替换已有视觉参考前确认。

“我的片单”保存独立收藏状态与互斥的想看/看过状态，可搜索片名和按状态筛选。
个人评分使用五颗星，半星对应 1 分，满星 10 分；未评分为 `null`，没有“0 分”按钮。
打分自动标记看过。清除评分保留看过；取消看过或改为想看则清除评分。
当前推荐电影保留并显示“已看过”，卡片以轻微透明灰色表示；已看影片在后续请求中排除。
片单分类为全部、收藏、想看、看过。“全部”中的“移除”先确认，再删除该片条目、所有标记和评分。
其他分类中的“移除”直接取消对应标记：取消收藏保留看过和评分；取消想看/看过保留收藏，
取消看过同时清除个人评分。清空整个片单仍需确认。

片单及星级以 schema 1 信封保存在当前浏览器 `movie_recommendation_library`，最多 500 部，
不包含推荐分数、原响应或身份信息。损坏/未知版本数据保留并显示警告，不自动覆盖；
存储不可用时提示当前修改未持久保存。旧反馈的看过记录仅在首次无片单时迁移，
旧喜欢/不喜欢/不感兴趣不推断成个人评分，也不随当前页面推荐请求继续发送。

### 片单里的评分偏好画像

“我的片单”新增默认折叠的评分画像，展开后可切换类型、导演署名、年代、国家 / 地区。
只统计当前片单中明确的整数 1–10 分：7–10 分正向、1–5 分负向、6 分中性。
同一类别的高低分分别计数、保留各自来源电影和分数，不抵消成一个喜好结论；
来源按钮打开已有电影详情。未评分、收藏、想看不推断偏好，中性记录单列。

每个维度显示资料有效的正向、负向、中性电影数及缺失数；只有一部来源的方向标记“单部，样本不足”。
空片单、全中性或全部缺资料时显示证据不足 / 无方向说明。每个维度先展示最多四项，

### 独立电影搜索

统一导航的“电影搜索”入口可独立检索电影。按片名搜索支持原名、译名和别名，
可限定首映年份；按类型与年代浏览使用TMDB类型列表与首映日期范围，按TMDB热度排序。
两种方式分开提交，片名模式不提供类型 / 年代的假筛选，条件浏览不携带隐藏片名或年份。

`GET /movies/genres` 返回类型列表；`GET /movies/catalog` 返回当前页、TMDB检索计数、上游总页数和可访问页数。
参数为 `mode=title` 加 `query` / 可选 `year`，或 `mode=discover` 加可选 `genre_id` / `decade`，
两者都支持 `page=1..500`。过滤由上游实际执行，分页也读取上游新页；不局限于当前候选的8部。
TMDB最多开放前500页，每页最多20部；检索计数来自上游，不代表电影库总量。
大范围检索本轮实际返回20,001部的计数，1990年代西部片则为264部，类型与年代确实参与上游筛选。
可进一步缩小范围后分别浏览。年代选项为1880–2029，不列出2030年及之后的年代。

检索不调用个人推荐排序，不自动发起推荐，也不提供播放资源。导演、片长、国家等
完整资料通过已有详情接口读取，卡片不补造缺失资料。

### 本地推荐历史

工作台“推荐历史”自动记录成功的推荐和“换一批”，最多保留最近20次；使用独立的
`movie_recommendation_history` schema 1浏览器存储，与片单、个人评分和实验数据分开。
每条保留需求、时间、参考电影ID或使用图片的标记、请求页码 / 换批状态 / 评分及排除数量，
以及当时返回的电影顺序、简介、分数构成、算法版本、推荐说明、解析条件、警告和调用诊断。
只保存白名单字段，不保存上传图片、文件名、文件路径、对象URL、历史评分明细或实验快照。

“查看这次结果”读取本地历史，不重新推荐、不重算分数；详情和片单操作复用现有功能。
当前收藏、看过和星级状态实时显示，改分不改变历史算法分数和原顺序。
历史文字与分数从浏览器存储读取，海报及主动打开的完整详情仍需要网络。
“填入这次需求”只填入文本及确切的参考电影，保留当前结果，并明确说明当前结果仍来自上次响应；
上传图片无法恢复，会提示重新选择，也可明确发起文字推荐。
每次点击“获取推荐”都发起全新的推荐，从第一页重新解析需求、召回候选并计算结果；
不读取过去的推荐结果，不把历史电影自动作为排除或偏好。当前片单评分和已看排除继续生效。
“换一批”才沿用本轮已展示排除；新推荐在更大的召回窗口中加权抽取候选后执行原有模型计算，

超出时淘汰最旧整条记录，单条过大则不保存并提示；浏览器实际配额失败保留旧数据，
当前页面仍可查看本次记录。损坏 / 未知版本原数据不自动覆盖，可显式清空后重新使用。
单条删除和清空历史分别确认，只影响这个历史存储键；取消保留记录。
同源标签页通过storage事件同步最近变化，网页来源不同则存储分别独立，例如localhost与127.0.0.1。

### 评分驱动的匿名偏好

页面已移除喜欢、不喜欢、不感兴趣按钮，星级成为唯一偏好输入。
每次推荐发送最近更新的最多 200 条有效评分到本机后端，所有片单已看 ID 另行排除。
评分、清除或移除仅影响后续请求，不自动重新请求或改写当前结果。
请求 `feedback` 使用 `schema_version=2, action=rating, rating=1..10`，附带确切 TMDB ID、
更新时间及公开简介、类型、关键词。后端拒绝缺失、0 分、非整数或版本错配。
旧 schema 1 动作仍受支持，仅用于既有 API/实验快照兼容，不转换或覆盖历史数据。

```text
偏好强度 s(r) = (r-6)/5，r < 6；(r-6)/4，r >= 6
电影相似度 = 60% × 本地语义向量 + 25% × 类型 Jaccard + 15% × 关键词 Jaccard
个人评分偏好分 = clip(0.5 + 0.5 × mean(s(r) × 电影相似度), 0, 1)
```

仅方向性评分（1–5、7–10）进入均值；6 分仅表示看过，不形成方向性偏好。
每条评分按一份归一化，保留 7 分与 10 分的强度差异。同一 TMDB ID 使用最新值。
相似度只在可用分量间归一化；ML 不可用时使用类型/关键词，明确返回 metadata 降级原因。
无评分或全为 6 分时，`user_feedback` 不可用，15% 配置权重自动分配给其他可用分量。
已评分影片视为看过，后端也会在召回前排除。评分资料仅供本地算法，不上传给 DeepSeek。

算法版本为 `personal-rating-hybrid-v2` / `personal-rating-metadata-v2`，融合版本
`availability-normalized-fusion-v4`。普通API/换批请求的推荐响应缓存包含评分数值、评分电影资料和融合配置；
修改评分或配置不会复用旧结果。主按钮每次携带 `force_refresh=true`，跳过整批推荐响应和原文解析缓存，
不写入整批结果缓存；JSON与multipart接口均支持该可选参数，缺省为false以兼容既有API/实验调用。
电影元数据和模型向量缓存继续复用。环境变量 `SCORE_WEIGHT_*` 的已有
覆盖配置保持有效；页面实际返回权重为准。本次权重调整是产品配置，尚无新质量提升结论。

验证与完整修改清单：[2026-10-08 详情、片单与星级验证](experiments/VALIDATION_2026-10-08_LIBRARY_RATING.md)。

新星级配置另有固定候选配对验证：两个合成偏好场景，各比较无评分与1、5、6、7、10分，
另含10分元数据反馈对照，共12组。每个场景共用候选、已看排除、真实语义向量、融合配置和MMR；
6分与无评分的完整排序及分数一致，方向性评分保留强度。真实源请求使用MPS，配对编码使用本地CPU。
结果与JSON/CSV/盲审模板见[配对导出](experiments/rating-pairs/export-2026-10-08/comparison.md)，
采集、严格离线复现及263项后端测试见[星级配对验证](experiments/VALIDATION_2026-10-08_RATING_PAIRS.md)。
这些评分是假设场景，未写入浏览器片单；独立相关性复核为0组，P@5/NDCG保持空值，没有质量提升结论。

质量分同时考虑 TMDB 评分和评分人数，避免少数人给出的极端高分占据首位。
文本相关度优先使用 `paraphrase-multilingual-MiniLM-L12-v2`：用户原始文本、
主题、喜欢元素、情绪、关键词和类型构成正向查询；明确不喜欢的元素不追加到
正向向量，并作为独立扣分证据。电影文本由片名、原片名、简介、类型、关键词、
导演、演员和可用主题组成。查询与电影向量均做 L2 归一化，评分公式为：

```text
cosine = query_vector · movie_vector
text_relevance = (clip(cosine, -1, 1) + 1) / 2
```

电影向量按实体类型、TMDB ID、模型名、模型版本、内容 SHA-256、维度和更新时间
存入 SQLite，数据以 float32 保存。简介、关键词或模型身份变化后旧缓存会自动
失效；损坏的缓存会被保留为 `.corrupt-*` 文件并自动重建。查询向量每次实时
编码，候选电影统一批量编码，不逐部加载模型。

未安装 ML 依赖、模型未预下载、离线、本地文件不完整、MPS 算子失败或维度异常
时，接口继续使用原词项评分，`text_relevance.available` 仍为 true，但证据明确
显示“词项降级”。只有真实图片向量存在时才启用视觉相似度；个人评分偏好在存在有效
方向性评分时参与，否则显示“未参与”。

### 推理并发与失败恢复（2026-10-08）

文本语义、图片向量和评分画像共用进程内 MPS 协调器，模型加载、MPS 编码及迁移到
CPU 依次执行。海报下载和 CPU 编码不占用设备锁；迁移完成后释放锁再重试 CPU。
原有模型级锁仍保证并发首请求只加载一次。此协调器仅覆盖单进程线程，不协调多个
Uvicorn worker，也不保证严格先进先出。`encode_ms` 包含本次等待共享设备锁的时间。

坏图片、零向量等数据错误明确降级，不因此迁移健康的 MPS 模型；MPS 运行时 / 算子
异常仍重试 CPU，重试也失败时保留词项 / 视觉不可用状态。默认仅本地加载先解析
固定版本缓存目录，再交给模型库，避免 Transformers 对仓库 ID 启动后台格式转换
检查；缺失文件不会自动联网补齐，模型名称、版本及向量缓存身份保持不变。
SQLite 向量缓存的连接在成功、回滚及初始化异常路径都显式关闭。

本轮自动回归和小规模真实 MPS 并发、坏图 / 恢复证据见
[稳定性加固验证](experiments/VALIDATION_2026-10-08_STABILITY.md)。可显式复现六请求核对：

```bash
.venv-ml/bin/python scripts/run_inference_stability_smoke.py --output /tmp/movie-stability-smoke
```

此脚本需当前 MPS 后端运行，会查询 TMDB，并可能调用已配置的自然语言解析服务；
其中评分和几何参考图片为测试数据，不写浏览器片单、实验标签或候选快照。
它验证请求可用性及降级，不能作为性能分布或推荐质量提升结论。

## 已知限制

- 运行依赖当前网络能够访问 TMDB。
- “低暴力”“治愈”等主观条件属于软匹配，不能完全替代影片分级判断。
- TMDB 的中文简介和海报可能不完整。
- 后端内存缓存会在退出后清空；推荐历史仅保存在当前浏览器，清理浏览器数据后会丢失。
- 文本模型是可选依赖；未执行显式预下载时会降级到词项匹配。
- 80条简介与元数据核对批次的来源为79条机器、1条人工，后续工作台状态更新另留审计。简介不能判断所有表演/视听要求，含未知项的池不计算相关性指标；该批次结果不等于人工真值或完整召回评估。
